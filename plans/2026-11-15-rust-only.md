# Rust as the only engine

0.7.0 checks with Rust by default; `SQLTY_AST=python` still selects the `ast` passes,
with a `FutureWarning`. 0.8.0 removes them. Between the two, what the Python package
still decides moves into the engine crates, so a TypeScript or Rust host (the
playground, VS Code, a Rust CLI) gets what `sqlty check` reports without Python. It
continues [the AST port](2026-11-07-python-ast-in-rust.md) and stage 4 of
[the host-agnostic engine](2026-11-03-host-agnostic-engine.md).

## What Python still does with `SQLTY_AST=rust`

Measured with coverage of `sqlty check`, `--fix`, `--statistics`, `rewrite`, `strip`,
`format` on `examples/`, and of `tests/mdtest`, `tests/test_cli.py`,
`tests/test_cross_module.py` and `tests/test_lsp.py`: no `ast` pass runs. What runs:

| Python | Does | Moves to |
|--------|------|----------|
| `_cli.ConfigSource`, `SettingsResolver`, `_config` | find the nearest config, apply `extend`, `include`/`exclude`, per-directory settings, schema per directory | `sqlty-python::project`, files through a host trait |
| `_cli._walk`, `_gitignore` | list the checked files | same; the host lists directories |
| `_cli._module_names`, `_checked_roots`, `Project._fill_index`, `_helpers.configured_helpers` | module names, the helper index, `[[tool.sqlty.functions]]` | same |
| `_check.RowUsage` | `redundant-optional` across files | `check_modules` |
| `_check.apply_suppressions` (`check_source`, `breaking_source`) | `# sqlty: ignore` for the library API | `suppress.rs`, already used by `check_modules` |
| `_queries` | `-- sqlty: ignore` in `.sql` query files | `suppress.rs` |
| `core.breaking_source`, `_breaking._compare`, `_snapshot` | what a schema change breaks; the snapshot format | `sqlty-python::breaking`; git stays in the host |
| `_lsp_bridge`, `_lsp_breaking` | the language server's workspace | `sqlty-lsp` over the Rust project |

Host glue stays in Python: argument parsing, output formats (text, JSON, SARIF, GitHub),
`git worktree`, the codec (`magic`, `_decode`), `sqlty.drivers`.
