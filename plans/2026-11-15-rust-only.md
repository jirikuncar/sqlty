# Rust as the only engine

> **Status:** every check runs in Rust since 0.8.0 (#1101 to #1111, #1156). Python
> still runs `complete`, `breaking` and `server`, and parses the command line (branch
> `cli/rust-only` moves that to `sqlty-cli`).

What the Python package still decides moves into the engine crates, so a TypeScript or
Rust host (the playground, VS Code, the native `sqlty`) gets what the Python CLI does. It
continues stage 4 of [the host-agnostic engine](2026-11-03-host-agnostic-engine.md).

## What Python still does

| Python | Does | Moves to |
|--------|------|----------|
| `_cli.ConfigSource`, `SettingsResolver`, `_module_names`, `_checked_roots`, `Project._fill_index`, `_helpers.configured_helpers` | settings, files and the helper index of `complete`, `breaking` and `server` | `sqlty-project`, which `check` already uses |
| `core.breaking_source`, `_breaking._compare`, `_snapshot` | what a schema change breaks; the snapshot format | `sqlty-python`; git stays in the host |
| `_lsp_bridge`, `_lsp_breaking` | the language server's workspace with a breaking baseline | `sqlty-lsp` over `sqlty-project` |

Host glue stays in Python: the codec (`magic`, `_decode`) and `sqlty.drivers`.
